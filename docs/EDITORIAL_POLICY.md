# Launch scope and editorial policy — Weeks 1–4

The pilot beat is U.S. AI infrastructure and policy. Federal Register documents
are the first primary-source intake; topic-search matches require editorial
screening. Every evidence record keeps its stable ID, original URL, publication
date and retrieval provenance. Additional historical sources are registered with
a date, publisher, original link and the operator's provenance note.

The implemented reader is account-free web HTML plus a public GET/HEAD API.
Editorial commands run separately under trusted operator/database access.
Native mobile installation, automatic refresh, offline caching and optional
alerts remain later milestones; these are not implicit in the web release.

Before approval, an editor checks every original source, whether it supports each
claim, the distinction between an event date and a publication date, historical
comparison limitations, and whether scenarios are conditional and have a trigger,
timeframe and observable signal. A source-reference check is not a factual review.
Record an explicit assessment and all checked source IDs. Do not approve real
reporting using the fictional example review file.

Publication is a separate operator action on the latest approved editorial
version. Ordinary new evidence uses an `update` publication. A factual error in
published reporting uses `correction`, with a public explanation of the precise
change. Both create a new publication and retain access to earlier versions.
Private audit notes and operator identities are excluded from public projection.

Alerts are not implemented or sent in this release. The later alert workflow
must require editorial approval and reader opt-in. A material change to an
approved story or an important factual correction is a candidate for review;
a routine metadata edit is not sufficient. Record the proposed reason and
avoid sending speculative scenarios as established events.
