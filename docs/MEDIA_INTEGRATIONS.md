# Story formats and integration runbook

Implementation: 24 November 2026. This extends the existing owner-private Worker;
it does not complete native iOS/Android, offline reading, push alerts or broad news coverage.

## Reader behavior

- Read: a source-derived evidence diagram by default; a reviewed image replaces it when available. Captions, alt text, credits and disclosures remain visible.
- Listen: chapter-based browser synthetic voice with pause/resume, stop, rate and transcript. Where a released recording exists, native audio provides seeking and speed. Browser voices depend on device/browser availability and are not saved recordings.
- Watch: chapter-based captioned storyboard with cited sources, optional browser voice and caption-only fallback. Released MP4s use native video with WebVTT captions and transcript. Storyboards are explicitly distinguished from documentary footage.
- New and corrected story versions select matching released assets only. Older published versions retain their own media. Rejected assets are withdrawn from listings and file delivery.
- Questions, corrections and source suggestions enter a separate review queue. Accepting feedback means further research, not automatic modification of claims.
- Interaction counts require browser opt-in. They measure opens/source clicks/play starts/completions, not unique users. No third-party analytics, cookies, IPs or identity columns in metrics; aggregate data older than 90 days is removed on writes.

## Editorial workflow

Open a story, then Editorial Review → Media studio. Create an evidence diagram or
storyboard, generate provider media when configured, or upload an existing asset.
Review previews, original source support, captions/transcript, credit, rights and
all generated content. A media decision needs a written assessment. Media cannot
be released until its latest underlying story version is editorially approved.
Research-preview rendering does not attest editorial approval.

Uploads accept PNG/JPEG/WebP, MP3/WAV or MP4, up to 20 MiB each. Headers and
file signatures are checked; SVG uploads and remote asset URLs are not accepted.
Images require alt text. Recordings require a transcript; videos also require
plain timed WebVTT captions. The owner must assess rights and factual support;
file validation does not prove either. Files are stored privately and served
through the authenticated application, including byte ranges for playback.

## Durable storage and migration

`.openai/hosting.json` retains the same project and D1 binding and adds R2 `BUCKET`.
Sites provisions/binds these resources when deploying. Drizzle migrations 0002
and 0003 add media, feedback, metrics and decision tokens; 0004 adds reference
and immutable-content guards plus query indexes. They contain no story data or
approval seed. Original tables, source history and publication guards remain.

API routes require editor identity; same-origin checks apply to mutations.
The existing source-intake service does not gain media generation, upload or
approval access. Uploaded/generated bytes and credentials are never in Git.

## Optional provider generation

Set these through the site's server-side environment configuration, never the
browser, repository, hosting manifest or a pasted key in chat:

| Variable | Purpose |
| --- | --- |
| `OPENAI_API_KEY` | Authorized provider credential |
| `EPSTMC_MEDIA_GENERATION=enabled` | Explicit enablement of paid generation |
| `EPSTMC_IMAGE_MODEL` | Available image-generation model supporting base64 PNG output |
| `EPSTMC_TTS_MODEL` | Available Speech API model supporting 24 kHz mono PCM |
| `EPSTMC_TTS_VOICE` | Optional standard voice (default `alloy`) |
| `EPSTMC_MEDIA_DAILY_LIMIT` | 0–50 paid jobs per UTC day, default 6 |

No default model is hardcoded: model availability and lifecycle must be checked
for the owner's provider account. Contracts consulted:
[Speech API](https://developers.openai.com/api/reference/resources/audio/subresources/speech/methods/create),
[PCM output](https://developers.openai.com/api/docs/guides/text-to-speech), and
[image generation](https://developers.openai.com/api/reference/resources/images/methods/generate).

Requests go only to fixed OpenAI HTTPS endpoints. Images are labelled generated
illustrations, not evidence. Narration extracts the existing story and preserves
historical limits, conditions and gaps. A job permits at most 20000 input
characters, six speech chunks of at most 3500 characters, one attempt per chunk,
and 24 MiB total PCM; samples become one WAV with correct duration. One 90-second
request deadline covers the generation operation. Images permit one image request
with bounded response bytes. Failed and ambiguous attempts consume the job slot;
reusing a request key returns the stored job rather than calling a provider again.
The daily job count is a usage bound, not a euro-denominated spending guarantee.

States: queued → generating → review → ready, or failed/rejected. Ready means an
explicit media review, not automatic generation success. Interrupted jobs older
than five minutes can be closed; retry is a deliberate new request and can incur
a new charge. An asynchronous external queue or webhook renderer is not configured.

Without provider credentials the reader's diagram, browser listening and visual
storyboard work. Uploads and review work once R2 is connected. Paid buttons remain
disabled and explain configuration; no paid call was performed during development.

## Video export

Download storyboard JSON from the media studio and use
[the MP4 renderer](VIDEO_EXPORT.md) to make a captioned MP4, transcript, VTT and
provenance metadata. Upload those outputs for review. FFmpeg runs on a workstation
or separate rendering worker; it is not available inside the hosted Worker.
The web application does not claim one-click hosted AI video generation.

## Validation and release evidence

The release checks cover byte validation, private access, story/media approval,
concurrent decisions, audit rollback, source-linked scripts, provider failures,
job limits, ranges, correction lineage, withdrawal, feedback and consent.
Rendering tests inspect real silent and narrated MP4s with ffprobe. Browser checks
cover reader modes and editorial media management. Provider tests use isolated
fixtures and never real paid calls or live editorial decisions.

See DAILY_DEVELOPMENT.md for exact check counts and deployment evidence.
