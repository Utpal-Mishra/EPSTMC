# Offline captioned video export

The private website provides an interactive source-linked storyboard. This
utility turns that same storyboard into an actual H.264 MP4 for media review.
It does not call a paid provider, approve a real story, or publish a file.

Requirements: Python 3.9+, Pillow, `ffmpeg` with libx264, and `ffprobe`.
Install Pillow in the renderer environment (`python -m pip install Pillow`).
The hosted Worker never runs FFmpeg; render on a workstation or a separate worker.

Save the media studio's storyboard JSON to a local file. Its contract is:

```json
{
  "title": "Story title",
  "story_id": "the-story-id",
  "story_version": 1,
  "story_hash": "the immutable story hash returned by the media API",
  "script_hash": "the script hash returned by the media API",
  "review_status": "draft",
  "scenes": [
    {"title": "Dated event", "text": "Qualified explanation.", "source_ids": ["source-id"]},
    {"title": "Coverage limits", "text": "What remains unverified.", "source_ids": []}
  ]
}
```

```bash
python scripts/render_explainer.py storyboard.json story.mp4
python scripts/render_explainer.py storyboard.json story.mp4 --duration 90
python scripts/render_explainer.py storyboard.json narrated.mp4 --audio narration.wav
```

The default silent storyboard is 75 seconds. `--duration` accepts 1–7200 seconds;
use a short duration for a smoke test and a longer duration for substantial text.
Scenes receive time in proportion to their word counts. Long scene bodies are
paginated into readable 29-pixel slides without deleting their qualifications.
The metadata flags a reading-speed warning when the duration allows fewer than
one second per three words. Review that warning before releasing a short video.
The full transcript preserves all supplied title/text and source IDs verbatim.
WebVTT escapes markup delimiters and uses a fullwidth colon in literal URI schemes
so captions satisfy the hosted plain-caption upload contract; the original URI
text remains unchanged in the transcript.

A full recording's actual duration, measured by ffprobe, overrides `--duration`.
Alternatively, add an `audio` filename to every scene. Those paths must remain
inside the storyboard file's directory. Per-scene recordings are measured
individually, decoded to a common PCM format, and aligned with their scene.
Do not combine per-scene recordings with `--audio`. Neither mode claims that the
operator's recording was generated by AI: its provenance remains a review task.

The output consists of:

- `story.mp4`: captioned visual slides; supplied narration only when specified.
- `story.vtt`: timed plain-text WebVTT captions.
- `story.transcript.txt`: complete text and source references.
- `story.metadata.json`: source IDs, timing, input/output hashes, disclosure,
  reading-speed warning, and `requires_editorial_review` status. Metadata preserves
  `story_id`, `story_version`, `story_hash`, `script_hash`, and `input_review_status`.
  Older exports using `version` and `hash` remain compatible.

Output files are protected from accidental replacement unless `--overwrite` is
passed. Audio is restricted to existing regular files, requests never use the
network, and FFmpeg runs with argument arrays and generated safe manifests.

Upload the MP4, transcript and VTT through Editorial Review → Media studio.
Supply the credit, rights and a truthful disclosure. Watch and listen to the
rendered result, check timing and sources, then record an explicit media review.
The underlying latest story must be approved before media release. Files are
bound to the selected story version; a correction requires refreshed media.

Validation:

```bash
python -m unittest discover -s tests -p test_render_explainer.py -v
```

The rendering tests create real temporary silent and narrated MP4s, inspect the
streams with ffprobe, and verify transcripts, captions and asset hashes. They
skip where optional renderer dependencies are not installed.
